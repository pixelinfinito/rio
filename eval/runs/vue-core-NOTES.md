## Observed Rio defects and reproductions

1. **Committed workspace changes block every baseline.** The reports have zero base check entries. For #12701, Rio says `baseline_failed: linked dependency packages/vue::@vue/compiler-sfc points at changed source packages/compiler-sfc: packages/compiler-sfc/__tests__/compileScript.spec.ts; commit or stash the linked package's changes`. For #15328 the analogous source is `packages/shared/__tests__/looseEqual.spec.ts` via `packages/compiler-core::@vue/shared`. These are clean, detached, committed PR heads, not dirty working-tree changes (runner git status and independent *-checkout-verification.json). Reproduce with either pinned runner command in commands.json and the supplied frozen install plan; forced reinstall reproduces it. There is no synthetic finding ID: this is check-level `baseline_failed` metadata, with all affected finding IDs in the per-PR defect-finding-index.json. The code read-only inspection of `check_compatibility` confirms it compares head-linked package source to selected base source; dependency trust cannot override a known mismatch. No setup-only repair has been established within the constraints, and crates/ were not edited.

2. **Package TypeScript fallback ignores Vue's ancestor tsconfig.** #12701 has no package-local tsconfig for compiler-sfc. Rio passes all package TypeScript files directly, omitting the root target, globals, path aliases, interop and strict-null settings. The independent root check has exactly the intended new TS2322; Rio omits it and generates unrelated diagnostics even on the clean base. Reproduce `python3 eval/runs/vue-core-setup/adapter-repro.py 12701 base /tmp/vue-positive-base 22.14.0` after preparing the pinned checkout/install. Exact expanded argv and output are in base-adapter-reproduction.json and base-adapter-typecheck-fallback.log. Example ID `0066225e0eb260cf4e9bc2f57cedb979a32bcb94571f033338acb75da754a515` is `Cannot find name '__DEV__'` in compiler-core; the root tsconfig includes packages/global.d.ts. Every affected ID is indexed in defect-finding-index.json. This setup/adapter defect is not scored as 405 product false positives.

3. **TypeScript 6 fallback fails with TS5112; general tsc errors are unparseable.** #15328 uses locked TypeScript 6.0.3. Most package checks fail before analysis with `error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline. Use '--ignoreConfig' to skip this error.` Direct reproduction is head-adapter-typecheck-fallback.log. The correct root `pnpm check` passes. Both PRs also have TS6504 from explicitly including JavaScript files without allowJs in dependent package invocations. Rio calls these `unparseable_output`; no finding ID is emitted for these check failures. Root fallback, rather than incorrect source, triggers them.

4. **Vitest 4 command includes removed --minWorkers.** #15328 direct adapter reproduction exits 1 with `CACError: Unknown option --minWorkers` before running tests. The exact pinned command is in head-adapter-reproduction.json and the error in head-adapter-coverage-package-root.log. Rio's coverage checks for every scheduled root fail `tests_failed`; there are no coverage finding IDs. The independent root instrumented test command, without the removed option, succeeds. Rio's generic hint says `usable coverage from the incomplete run is retained` even on this startup failure; no usable coverage was produced in this reproduction.

5. **Vitest 3 workspace config resolves from the wrong cwd.** #12701 direct adapter reproduction fails at startup because `../../vitest.workspace.ts` resolves `vitest.unit.config.ts` relative to packages/compiler-sfc, where that file does not exist. base-adapter-coverage-package-root.log contains the exact error. The config file exists at the repository root. No coverage finding ID is emitted; check outcome is `failed/tests_failed`.

6. **pnpm nested peer directory normalization produces false missing-package setup errors.** #12701's playground/debug checks report @vitejs/plugin-vue missing although it is installed and resolvable. plugin-vue-resolution.txt records Node's successful resolution and actual directory `@vitejs+plugin-vue@5.2.4_vite@5.4.15_@types+node@22.14.1_sass@1.87.0__vue@packages+vue`. Rio's installation parser substitutes/removes parentheses differently. Reproduced after the forced reinstall; tracked lockfile is unchanged. The doctor also reports missing nested-peer packages at the root. No finding ID: these are `dependency_mismatch` skips. Do not mislabel them as vulnerability findings.

7. **Dependent roots amplify incompatible checks and confusing classifications.** #12701 schedules compiler-sfc plus seven transitive consumers (dts projects, Vue, compat, SSR, playground/debug); #15328 schedules 16 roots because shared is widely imported.
