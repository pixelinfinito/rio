# v0.3 QA acceptance record

Evaluation completed on 2026-11-09. All 18 labeled cases were attempted with both
Codex and Pi, and all 36 selected reports are retained. **Every broad evaluation
report is partial; this is not a successful full-matrix acceptance.** The default
budgets yielded poor coverage and many misses. The separate focused UX assessment
and hosted/local checkout verification completed successfully within their scopes.

Tasks 8.1–8.2 require an evaluator and an honest record of detections, misses,
noise and cost; they impose no minimum recall. This record fulfills those tasks
without treating evaluation completion as a model-quality or release-readiness
claim. Improving default-budget coverage and reducing clean-flow noise remain
product-quality concerns.

The runs used `custom-node-openai/gpt-6.1-sol` through the AI Gateway custom
endpoint. Scoped, immutable `REVIEW.md` guidance and the versioned UX rubric were
available to journey execution and verification. The implementation covers task
completion, clarity, efficiency, recovery, control and inclusive interaction,
as well as visual UI checks. Recommendation quality is assessed separately from
defect detection, and a supported recommendation does not prove its proposed
benefit.

## Build provenance and failed attempts

The broad runs span implementation fixes; they are not a controlled comparison
of one final build. Original reports and misses remain intact. Preferred retries
are selected by path availability, never by detection success. The selection
policy and report hashes are in the matrix summary.

Live acceptance led to regression-tested corrections for scrollable/focus-revealed
content, immutable requirement/rule/browser-target identity, preceding/current-step
evidence, modified CSSOM trace sanitization, gateway redirects, and partial
checkpoints. Checkpoints now expose collected candidates, recommendations and
assessment at the top level while leaving run-wide minority rules unfinished.
Earlier runs could lose collected candidates on interruption; their misses have
not been retrospectively relabeled. The corrected QA image digest is
`sha256:ae1ca1fcac035c4d7d05b8c54eb9d8b01a7d586ce0de0dc7c8721e248ab65d7f`.

Hosted attempt `dad36e5a-39bb-4038-9fad-9f90bc1c34c2` exhausted voter budgets.
Attempt `ccd5364a-98b7-4be2-972d-8d4faebb5165` resolved that issue but returned an
invalid evidence enum. Compact evidence packs, explicit enum instructions and the
bounded, charged schema-repair loop resolved both in the final comparison.
Earlier upstream/proxy interruptions did not count as successful acceptance.

An isolated keyring collision prevented the first Pi contrast attempt from
starting. Disk exhaustion later prevented four QA starts and one fixture Git
initialization. Stale compiler cache from this worktree was removed while
preserving source, binaries, reports, evidence and other worktrees. All five
unstarted cases were retried, as was Pi contrast. The final six selected retries
are Codex ambiguous-next/lost-input/missing-cancel and Pi
low-contrast-dark/lost-input/missing-cancel. Their replacement reports still retain
budget interruptions. The evaluator now records fixture setup failures and
continues to later cases without fabricating reports.

## Verification and reproduction

The full Rust workspace suite, real Docker seed/pod/authoring acceptance, CLI
examples and six installed Codex/Pi protocol tests passed earlier in this change.
The Worker suite passed 387 tests before the final schema repair; all 63 affected
Worker tests passed afterwards, with type/contract/bundle checks. Controller
validation passed 104 unit tests and five composed browser tests after checkpoint
retention. The updated Sandbox overlay passed five real integration tests for
provisioned static/vendored apps, Dockerfile deferral, missing dependencies and
cancellation cleanup. Final verification passed all 107 evaluation tests, checked
all 36 source report hashes and rescored metrics against the portable summary,
and rechecked hosted/local identity, occurrences and votes. Strict OpenSpec
validation, generated QA assets and `git diff --check` passed. CodeRabbit could not run because authentication required
renewal; no external review approval is claimed.

To reproduce with a configured host route (real model usage is charged):

```sh
cargo build -p rio-cli
docker build -f worker/Dockerfile.qa -t rio-qa:0.1.0 .
python3 eval/qa/run.py --local --harness codex --output /tmp/qa-codex
python3 eval/qa/run.py --local --harness pi --output /tmp/qa-pi
```

For offline rescoring of a retained case directory, use its exact report/cache:

```sh
python3 eval/qa/run.py --reports /tmp/rio-qa-expanded-retries-final/pi/low-contrast-dark \
  --case low-contrast-dark --output /tmp/qa-rescore \
  --labels docs/evaluation/v0.3-qa-human-labels.json
```

The [evaluation README](../../eval/qa/README.md) documents matching, labels,
per-cell costs, setup failures and exit codes. Reports with no completed cells
exit 2; a zero evaluator exit is not proof of complete matrix coverage. Portable
summaries are repository evaluation artifacts; the original `/tmp` browser caches
are machine-local and must be retained separately for future evidence inspection.
