## Setup

- **Cases.** The 13 primary cases of the candidate set (CT-POS-01..05, CT-CL-01..02,
  SE-POS-01..04, SE-CL-01..02), pinned at full SHAs. Reserves were not run.
- **Endpoint.** The deployed endpoint configured in `~/.config/rio` on the maintainer
  machine, with runner image `rio-runner:0.2.2`. CLI:
  `rio review --base <base> --format json --profile <profile>` at the pinned head,
  from a release build of this branch.
- **Profile.** [`v0.3-agents/profiles/security-openrouter.yaml`](v0.3-agents/profiles/security-openrouter.yaml)
  extends `rio/security` (security step enabled, `posture: thorough`,
  `catalog: asvs-5.0`). It adds the models and review budgets of `rio/openrouter`,
  because `rio/security`, like `rio/base`, carries no models and a 100k-token budget.
  - Models: generator `openrouter/anthropic/claude-sonnet-5.5`, voters
    `openrouter/openai/gpt-6.1-sol`, 3 voters with quorum 2.
  - A triage rule disables the correctness agent, so the spend goes to the two agents
    under evaluation. The contracts agent is selected by triage's `public_contracts`
    signal as in any review.
- **Three runs.** Each case is scored on exactly one review, its run of record. The
  other outputs are kept as superseded evidence and are not scored.

## Failures and open concerns

1. **Fixed: a malformed tool batch ended the whole review.** This was CT-POS-01 and
   CT-POS-04 in the first run.
   - Cause: the security agent requested more than 8 tools in one turn, or drifted
     into native tool-call syntax and returned an empty tool list. `converse` threw
     `malformed tool output`, and the Workflow ended the review `partial`, discarding
     the other agent's work.
   - `f85cc11` runs the first 8 calls of an oversized batch and answers the rest with
     the limit. It sends an empty tool list through the repair turn, and one agent's
     failure now ends only that agent; a failed security conversation leaves its
     items unassessed as `tools_unavailable`.
   - `d65812c` also repairs null replies and nameless tool entries.
   - Both cases completed on rerun.
2. **Fixed: agent isolation held when a provider reply lacked content.** In the first
   rerun, CT-POS-05's contracts agent failed on a router reply without content or
   usage. The review stayed `partial`, kept its deterministic findings and noted the
   failed agent.
   - `61c309e` retries one transient provider failure (429, 5xx, or a reply without
     content or usage) after 2 s.
   - It also elides old tool results once a conversation exceeds 160 KiB, and bounds
     the verifier's blind context.
   - CT-POS-05 completed in the second rerun.
3. **Fixed during the pilot: the contracts agent was never selected for a Python CLI
   change (CT-POS-02).** Triage's `public_contracts` signal compared only TypeScript
   `export` and Rust `pub` lines.
   - `5febaeb` builds the signal from the inventory's contract surface.
   - The CT-POS-02 pilot from before the fix is superseded.
4. **Open cost concern: CT-POS-04 costs USD 4.24 and still exhausts votes.**
   - Its run of record used about 1.9M generation tokens: 1.47M (USD 2.97) by the
     security agent and 0.45M (USD 0.93) by the contracts agent.
   - The security agent still ended with every applicable item unassessed for
     `budget`.
   - Only 1 of 3 verifier votes completed, after the review budget was raised to 2.4M
     (`ba77f3b`).
   - Residual vote exhaustion remains on CT-POS-05 (5 of 6 votes complete). CT-POS-03
     completed all 6.
   - Repositories of polar's size (5,222 files, very large generated OpenAPI files)
     need either a bounded security conversation or a per-step budget split, before
     a `rio/security` review's cost is predictable.
