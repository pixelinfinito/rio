# QA UX review hillclimb (2026-11-10)

An iterative attempt to raise the quality of Rio's browser-QA UX review against a fixed, judged eval. Raw transcripts and
per-round results are machine-local and not committed. The runner and judge in `eval/qa/` reproduce them.

## Result

| Round | Change | Held-out | Train |
|---|---|---|---|
| 0 | Baseline | 0.704 | 0.644 |
| 1 | File every noticed friction; "assessed" means nothing left to file | 0.736 | 0.872 |
| 2 | Tool descriptions state the filing formats the controller accepts | **0.769** | 0.878 |
| 3 | `step_done` returns a masked viewport screenshot | 0.745 | **0.894** |

**The held-out gain (+0.065, paired 95% CI ±0.128) is inside noise.** With 9 held-out cases at 2 reps, the eval cannot show
that the review improved on unseen friction. Train rose by +0.23 to +0.25 (±0.21), just outside noise. Unsupported findings
rose from 0 to 5–7 per round, mostly speculative low-priority advice.

The earlier weak result was mostly about coverage, not review judgment. With a 300k-token cell budget, the unchanged review
already scored 0.70 held-out, with no unsupported findings on clean flows. The default-budget matrix in
[v0.3-qa-local.md](v0.3-qa-local.md) produced no recommendations because many cells never completed.

## What changed and why

- **Round 1:** the agent noticed friction in steps that technically passed, named it in an assessment reason, then marked
  the criterion assessed and filed nothing (6 of 13 train cases). The prompt now requires every named friction to be filed
  and adds a per-step check against generic heuristics.
- **Round 2, a defect fix:** the controller silently rejected about 48 filings per 26 runs on formats the tool descriptions
  never stated (rubric URL citations, live CSS selectors, `kind` matching the rule category). After the fix, none were
  dropped.
- **Round 3:** the agent's tools returned text snapshots only, so visual friction (hierarchy, focus outlines) was
  invisible to it. `step_done` now returns a CSS-pixel JPEG masked by the same page style as retained evidence. The proxy
  resends only the latest screenshot, so the unchanged byte-based cell budget does not pay for old ones. For Chat
  Completions providers, images move out of tool messages into a following user turn, because gpt-6.1-sol misread images
  placed inside tool messages. It caught a demoted retry action (0 → 0.5) and a blocking account prompt (0.50 → 0.96), but
  losses on other cases offset those gains, and cancelled cells rose from 4 to 7. Sending page pixels to the model provider
  is a policy decision to make before relying on it.

## Eval

- **Runs:** `eval/qa/hillclimb.py` runs focused journeys (mobile/light, Codex, `gpt-6.1-sol` through the AI Gateway).
- **Cases:** 13 train cases and 9 held-out cases, each run at 2 reps. 15 new fixture friction variants use neutral flag names
  (`variant-N`), because the fixture exposes active flag names in the page.
- **Judge:** `eval/qa/judge.py` runs `claude-opus-5-5` through the gateway's `custom-node-anthropic` provider. It grades
  model-authored recommendations and observations against grader-only ground truth (`eval/qa/frictions.json`).
- **Scores:** a friction case scores 0.5 × found + 0.5 × the best item's quality (adherence, relevance and actionability,
  each 0–2). A clean case scores 1 / (1 + unsupported items).
- **Calibration:** the judge matched the owner's two labels (2/2/2, no benefit claim).
- **Ground-truth fixes:** two real app quirks were added to the ground truth after the agent reported them correctly: a stale
  decline alert after a successful retry, and focus lost on re-render.
- **Counting rule:** reports from cancelled cells are graded. Runs with no report are retried.
- **Infrastructure caveats:**
  - Each QA run leaves untagged app images in Docker. About 250 accumulated and app preparation timed out. The runner now
    prunes dangling images before each pass.
  - About 1 in 10 runs hangs until the runner's 40-minute timeout.

## Follow-ups

- **Default budgets and matrix coverage.** These drive the weak full-matrix result.
- **Keyboard journeys.** These exhaust their budget at about 200–230k tokens, because every key press returns a full
  snapshot. Fix this with a repeat count on `press_key` or smaller post-key snapshots. The removed-focus-outline case scored
  0 in every round for this reason.
- **Probe results.** Route the deterministic probe results (focus style, labels) into the judged review instead of relying on
  model perception.
- **Noise.** A round aimed at reducing speculative recommendations.
- **Held-out set.** Add more held-out variants. Nine cases cap what the eval can show.
