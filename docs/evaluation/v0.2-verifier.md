## Blockers found

Every arm failed before verification. In order of the number of cases affected
(HS-RS-04 is counted under both 1 and 2, one per arm):

1. **Generation prompt exceeds the token allowance (10 cases in at least one arm).**
   `worker/src/workflow.ts` puts the runner's base and head impact graphs
   (`dataBlock("graph", graphs)`) into every agent prompt. Since the graph-scale
   change these graphs cover the repository: 238 KiB of JSON for urllib3,
   2.2 MiB for attrs and 3 MiB for ruff. `converse` in `worker/src/gateway.ts`
   bounds input by its UTF-8 byte count and refuses the call when it exceeds the
   agent allowance (80,000 tokens on the fast budget; 100,000 per agent on deep).
   The review ends `partial` with "token budget exhausted" and no model call.
2. **Workflow step timeout or runner analysis failure (8 cases).**
   `WorkflowTimeoutError: Execution timed out after 240000ms` or `checks: runner
   analysis failed` on astro, cargo, ruff, fastapi, tokio and clap. These are
   mostly the larger repositories.
3. **Git submodules are rejected by the CLI (4 cases).** `unsupported file mode
   160000` (aiohttp `vendor/llhttp`, undici `test/fixtures/cache-tests`, h3
   `standard-context`). The CLI exits 3 before upload.
4. **Submission rejected with HTTP 400 (2 cases).** starlette and tokio #8010
   uploaded their snapshots, then the review submission returned HTTP 400. The CLI
   does not show the response body.
5. **Malformed model output (1 case).** zustand (17 KiB of graphs) reached the
   generator in both arms, and the output was rejected as malformed.

Even without these, the harness only scores `status: complete` reports. Every
hosted review recorded so far, including the 2026-11-06 smoke runs, is at best
`incomplete`, because the runner skips the typecheck, lint, coverage and
dependency-audit checks (`tool_missing`, `offline`). Unless the runner image and its
egress provide those checks, or the gate is changed to ignore deterministic
skips, no case can be scored even after the blockers above are fixed. That is a
decision for the owner, not something to change in the acceptance harness after
a failed run.

## Adjudication

Because no agent finding exists, there is nothing to give a per-finding verdict.
The 18 verdict skeletons in the private run directory list no findings and name no
reviewer. The pre-run labels the candidate set requires are still open for the
owner, in [`v0.2-verifier/labels.json`](v0.2-verifier/labels.json):

- for each `HS-*` case, confirm the defect, its cause and its severity, and agree
  the detection rule (file plus symbol, and whether a different explanation at
  the same symbol counts);
- for each `CL-*` case, make an independent clean assessment before setting
  `independently_clean`; the manifest sets it to `false` for every case until then;
- record any swap for a reserve (for example the four submodule cases, if
  submodule support is not added) with its reason, before any new run.

## What has to happen before a rerun

1. Bound the graph context sent to agents (an impact slice, not the repository
   graph), or size the allowance check to it, so that agents on real
   repositories reach the model.
2. Fix or explain the 240-second step timeouts, the runner analysis failures and
   the HTTP 400 submissions, and support (or explicitly skip) submodule entries in
   snapshots.
3. Decide whether skipped deterministic checks should block scoring. Then either
   provide the tools and the OSV egress in the runner or change the gate, before
   the rerun rather than after it.
4. Complete the owner labels above, then rerun both arms on the same 24 cases
   with the same arm profiles and adjudicate every finding independently.
