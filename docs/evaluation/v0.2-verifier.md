# v0.2 verifier comparison (pinned acceptance): live run 2026-11-08

**Result: accepted on the owner's adjudication.** Both arms ran on 23 of the 24 approved
cases against the deployed endpoint; the owner recorded every rendered agent finding as a
true positive and confirmed every label without an independent review, so the precision
below (100 % in both arms) is an owner-adjudicated figure, not an independent
measurement. What does not depend on a verdict: 8 of the 11 scored high-severity
controls were detected, by both arms alike, so the quorum lost no control to the
single-verifier baseline; no arm produced a finding on 5 of the 12 clean controls, and the
findings on the other 7 were accepted by the owner. Task 1.1 of the archived
[`rio-v0-2-review-convergence`](../../openspec/changes/archive/2026-11-07-rio-v0-2-review-convergence/tasks.md)
closes on this record.

`execution: live-model`). Per-arm run index with the endpoint review ids, routes, costs

## Setup

- Case set: the approved 24 cases of [v0.2-verifier-candidates.md](v0.2-verifier-candidates.md),
  unchanged. HS-RS-03 (astral-sh/uv) was dropped by the owner after the run: both arms
  were cancelled by the review wall budget on the fast tier (8 min) and again on the deep
  tier (15 min); its snapshot is 24.6 MiB over 2,224 files and its graph is truncated at
  `max_nodes`. It is recorded in the run index as dropped and is not scored.
- Endpoint: the deployed endpoint, redeployed during the run from `main` at `e367629`
  (stage 3 and the custom gateway providers) plus the fixes listed below; runner image
  `rio-runner:0.2.3`.
- Models: generator `claude-sonnet-5.5`, voters `gpt-6.1-sol`, 3 voters with quorum 2
  in the quorum arm and `verify.voters: 1` in the baseline arm. Two routes to the same
  models: OpenRouter (`rio/openrouter`, the pinned profile) until its credit limit
  returned HTTP 402 part-way through the first pass, then the account's AI Gateway custom
  providers through the arm profiles
  [`quorum-custom.yaml`](v0.2-verifier/profiles/quorum-custom.yaml) and
  [`single-verifier-custom.yaml`](v0.2-verifier/profiles/single-verifier-custom.yaml),
  which differ from the pinned profiles only in the model route. The manifest records the
  route and profile hash per case; four cases (HS-TS-02, HS-TS-04, HS-RS-01, HS-RS-02)
  have one arm on each route. Costs on the custom route come from per-token prices
  derived from the OpenRouter-routed calls of the same models (USD 1.98/9.90 and
  0.92/4.18 per million input/output tokens).
- Agent result cache: the stage 3 cache served the generation of the second arm on the
  same change in several cases (marked in the index), so those arms share hypotheses and
  differ only in verification, which is what the comparison measures.
- CLI: release build of the acceptance branch; `rio review --base <base> --format json
  --profile <arm>` at the pinned head, two cases at a time, arms sequential per case.
- Raw reports, audits, resolved profiles, stderr and verdict files are kept privately
  under `~/.local/share/rio/verifier-v0.2/2026-11-08/` on the maintainer machine and passed
  `eval/credscan.py`. Provider spend for the arms of record: USD 25.40; including the
  arms superseded by reruns and the first, credit-limited pass, about USD 40.

## Owner acceptance (2026-11-08)

The owner accepted this run instead of commissioning an independent review:

- The 46 `verdicts.json` files name `Marcos Lisboa (owner)` as reviewer with
  `verdict_source: human`. Every rendered agent finding carries `true-positive` with the
  evidence text "accepted by the owner on 2026-11-08 (no independent review)"; findings at
  a registered control location carry that `control_id`.
- `labels.json` records the owner confirming each positive's defect, its introduction by
  the change and its severity, and each clean control as independently clean; its status
  is `owner-adjudicated 2026-11-08`.
- The scoring rule changed the same day: `eval/verifier.py` scores a review that is
  `incomplete` only because the hosted runner skipped deterministic checks (missing tools,
  no project configuration, no network), which is every hosted review; failed checks,
  missing votes and partial reviews still cannot be scored.
- An independent re-adjudication can replace the verdict files at any time; the harness
  re-pins and re-scores them.

## Product fixes made during the run

The first pass on 2026-11-08 and the resumes exposed faults that were fixed and
redeployed before the affected arms were rerun; earlier outputs stay in the private run
directory as superseded evidence.

- PR #8: one malformed hypothesis no longer ends the agent step; a lost sandbox container
  is retried under a new job id; the runner bounds its graph artifact to 4 MiB per version
  (tokio's exceeded the 12 MiB artifact limit and the job was killed).
- PR #11: a result of the wrong shape ends only that agent; a generation result wrapped as
  `{"hypotheses": [...]}` is accepted (clap, undici); a security result needs its
  assessment lists; the per-turn output cap is 16k tokens (undici's reasoning model
  returned 4096 tokens and no text, three runs in a row).
- Infrastructure: OpenRouter's credit limit (HTTP 402) ended the first pass; a full disk
  on the maintainer machine ended one resume; a branch switch removed the arm profiles
  during another. None affected a scored arm.

## Previous attempt (2026-11-07)

The first live run of the same 24 cases failed before any model call in every arm:
agent prompts carried whole-repository graphs, submissions exceeded the body limit,
the runner failed on invalid test-fixture manifests, submodules were rejected and
model replies in native tool syntax were discarded. Those were fixed in PR #5 and
confirmed by pilots before this run; its record is kept in the git history of this file.
