# Glossário

| Termo | Significado |
| --- | --- |
| Perfil | Política YAML: etapas, modelos, limites e regras de falha |
| Endpoint | Seu coordenador hospedado; distribui tarefas e chamadas de modelos |
| Runner | Host isolado de execução de código/ferramentas |
| Snapshot | Código base/alteração selecionado e imutável |
| Base comum | Ancestral Git compartilhado usado na revisão de branches |
| Achado | Problema com identidade, localização, categoria, severidade e evidência |
| Nível de evidência | Força do suporte, diferente de impacto/severidade |
| Baseline | Observação da base usada para distinguir problemas introduzidos |
| Preexistente | Já existia na base, em vez de ser introduzido pela alteração |
| Incompleto | Parte da análise não terminou ou foi ignorada; não indica ausência de problemas |
| Linhagem | Rodadas relacionadas de uma branch ou PR |
| Supressão | Política explícita que exclui achados correspondentes |
| Quórum de verificação | Avaliações independentes conforme requisitos de evidência |
| Conselho | Avaliações/experimentos independentes adicionais para incertezas |
| Jornada | Procedimento no navegador com objetivo, passos e sucesso |
| Célula | Execução de uma jornada em viewport/esquema de cor |
| Seed / fixture | Dados sintéticos reproduzíveis / entrada ou serviço controlado |
| SARIF | Formato padrão de resultados para análise de código |
