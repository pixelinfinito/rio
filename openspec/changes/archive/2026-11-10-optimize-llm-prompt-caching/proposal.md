# Proposal

## Why

Every Rio model call resends a large prompt: the agent's review context (graph excerpts, changed code, checks, guidance) is often 40–80 KB, a voter's blind context can reach 48 KB of code, and each tool turn resends the whole conversation. Providers now discount a reused prompt prefix heavily (Anthropic cache reads at 0.1× or less of base input; OpenAI cached input at up to 95 % off). Rio gets almost none of that benefit, and it cannot tell how much it gets, because of the problems below. The last one is a privacy gap rather than a cost problem. Each was checked in the current checkout.

1. **The verifier changes its system prompt mid-conversation.** `converse` (`worker/src/gateway.ts`) adds the vote-answer schema to the system prompt for `verify-disclosed` and the hypothesis schema for `verify-blind`. The system prompt comes first in every wire format, so the disclosed turn can reuse none of the voter's blind conversation, although its messages are the same.
2. **Agent prompts name the agent first.** The agents step's generation prompt (`ReviewWorkflow`, `worker/src/workflow.ts`) opens with "Review the change independently for ${agent}." and only then gives the shared instructions and the review context. Agents in one review run one after another on the same model by default, yet their prompts differ from the first sentence on, so none of them reuses the review context.
3. **Council rounds share no prefix.** `memberRequest` (`worker/src/council-pack.ts`) starts the user content with "Round N. Your role is …" and puts the rendering after it. Round 2 for the same member therefore misses everything after the system prompt.
4. **Anthropic routes never ask for caching.** Anthropic caching is opt-in through `cache_control`. Rio sends `system` as a plain string and no breakpoints on built-in, gateway or `custom-*` Anthropic routes.
5. **Cache usage is thrown away, and on Anthropic it would be under-counted.** The gateway reads only `input_tokens`/`output_tokens` (Anthropic) or `prompt_tokens`/`completion_tokens` (OpenAI). OpenAI-family routes already cache automatically, but `prompt_tokens_details.cached_tokens` and `cache_write_tokens` are lost. Anthropic's `input_tokens` excludes `cache_read_input_tokens` and `cache_creation_input_tokens`. If caching were turned on without normalizing usage, budget accounting would under-count input, and so would any upstream that reports cache fields on its own. The `usage` table, the report's `verification_usage` and the self-hosted runner (`crates/rio-runner/src/model.rs`) have nowhere to put cache tokens.
6. **Local cost estimates ignore cache pricing.** `MODEL_PRICES` has only `input` and `output` rates. Cached reads are priced as full input and cache writes are not priced at all, so an estimate cannot be correct once caching happens. OpenRouter's `usage.cost` is already provider-reported and stays the preferred source.
7. **Compaction churns the prefix.** `elideOldToolResults` elides just enough to get back under 160 KB. Once a conversation is near the limit, every turn can elide another older result, and each elision invalidates the cached prefix from that message on.

8. **Tenants can share private prefixes.** A deployment uses one provider key, so all its tenants share one provider cache. On automatic-caching routes a tenant who can guess another tenant's content (an open-source diff) could already tell from cache usage or latency whether that content was reviewed recently.

None of this needs a model, policy or tool-protocol change to fix. It needs a deterministic, layered prompt layout with a tenant partition, provider-aware cache hints, honest usage accounting, and a switch and quality gate for every change the model can see.

## What Changes

- **Layered prompt builder.** A single builder (`worker/src/prompt.ts`) assembles every model request Rio builds (Worker generation, verification and council calls) from ordered layers: shared protocol and schemas, stable instructions, tenant partition, review context, the current assignment, then append-only conversation. Layer boundaries become optional cache breakpoints. For identical inputs the builder produces byte-identical text and ordering. Where no breakpoint is rendered, the parts are joined into one plain string, in today's body format.
- **Tenant partition.** An opaque value per tenant and provider, derived from a random per-tenant secret kept in D1, sits between Rio's shared public layers and the first repository-derived content. Public layers stay reusable across tenants; private prefixes no longer are. Always on, on every route, and merged only with its quality gate passed. No deployment secret or rotation is needed. Each review fixes its switch settings when it starts, so replays rebuild identical requests, and a model echoing the value never reaches stored output.
- **Verifier prefix kept across the blind/disclosed boundary** (`verifier-system`). Both verifier phases use one system prompt. The vote-answer schema and the disclosure instructions move into the disclosed user message, which is appended only after the blind result has been persisted. Blindness is unchanged. The disclosed turn now reuses the voter's whole blind conversation.
- **Agent prompt reordered for reuse within a review** (`agent-order`). Shared instructions come first, then the review context identical across agents (intent, lineage findings, graph excerpt, checks, changed code, scoped guidance), then the agent's own instructions, data blocks (contract inventory, security catalog, taint map) and focus. The prompt text itself is unchanged. The agent result cache's prompt hash includes the layout version and enabled features (not the partition), so hits recorded under another layout are not reused.
- **Council request reordered for round reuse** (`council-order`, sequenced after `rio-v0-3-council` task 7.3, which runs on a pinned pre-change build). System and rendering come first, then the round header and the round-2 blocks.
- **Capability-aware cache hints per route.** Built-in Anthropic routes, direct or through the gateway, get at most three explicit `cache_control` breakpoints: the system prompt, the end of the reusable context, and the tail of multi-turn conversations. Custom Anthropic-protocol providers get them only when the deployment declares the capability. OpenAI built-in routes get a tenant- and conversation-scoped `prompt_cache_key`; on GPT-5.6+ this helps within a conversation and across one hypothesis's voters, not across agents, and Rio claims no more. OpenRouter Anthropic and Gemini models get content-part `cache_control`. `compat/`, `dynamic/`, custom OpenAI-protocol and `OPENAI_BASE_URL` routes receive no new fields. The `PROMPT_CACHE` Worker variable enables hint classes (`anthropic`, `openai`, `openrouter`) separately, or `off`; every class is off by default until its gate passes, `openai` included.
- **Normalized usage.** Every response is reduced to total input, cache-read input, cache-write input, uncached input and output, with no double counting. Token budgets keep charging total input, so caching never lets a review exceed its token limit. Only routes whose usage convention is documented and fixture-checked (Anthropic protocol, built-in OpenAI) have their cache counts trusted; there, malformed cache fields fail the call without a retry, since the reply may have been billed, and the call keeps its whole reservation. On every other route, self-hosted included, Rio charges `prompt_tokens` as today, records the counts as unverified, and records malformed ones as `null` and `invalid` without failing the call, so no route fails more often than today.
- **Transparent cost.** Each usage record states where its cost came from: `provider` (OpenRouter `usage.cost`), `estimate` (`MODEL_PRICES` with optional `cache_read` and `cache_write` rates), or `unknown` (`null`) when cache tokens were used and no rate covers them. Rio never invents savings or prices.
- **Compaction as an explicit checkpoint** (`compaction`). Elision runs only when history passes the high-water mark (160 KB). It then elides oldest-first down to a low-water mark (96 KB), and each checkpoint is recorded in the conversation audit. Its effect on the prefix is predictable and rare.
- **Measurable effect.** Usage rows, the review audit and the report's `agent_audit.prompt_cache` carry per-phase cache-read and cache-write tokens, the usage convention, how many calls reported cache fields, and cost sources. Model-call records carry layer hashes, never prompt text, secrets or cache keys.
- **Separate switches and milestones.** The `PROMPT_LAYOUT` Worker variable enables `agent-order`, `verifier-system`, `compaction`, `council-order` and `qa-order` one by one; all are off by default. Unknown values are rejected by `rio deploy`, at review submission, and before any reservation. This change implements and tests each feature. Turning one on by default is a later step, taken only after its gate passes on the live procedure or eval within fixed non-inferiority margins; a test fails any default that lacks a passed gate record.
- **Response cache stays off, voters stay fresh.** `cf-aig-skip-cache` stays on every gateway request. Byte-identical voter requests are still separate provider generations. Voters are not serialized or pre-warmed by default.
- **QA review calls** (after PR #17, `rio-v0-3-qa`, merges). The QA transport reports usage honestly (today it passes Anthropic's uncached remainder as total input and tells the harness `cached_tokens: 0`). It renders a replaced stale screenshot in the same message and position as the screenshot, so history is no longer re-shaped one turn later, then applies the same per-route hints to Codex and pi requests, hosted or local, with markers that survive screenshot replacement, a key per run and cell, and any harness cache field dropped. A `qa-order` layout feature moves run-stable content (criteria, guidance, origins) ahead of the journey and cell in the journey prompt, so journeys of one run share a long prefix instead of diverging at the first JSON field. QA voters keep their order, get the partition and keep screenshots inside the cached prefix.
- **Opt-in live measurement procedure** (documented, not run in this change). It measures real cache reads, writes, latency and billed cost with controlled cold and warm requests, and defines each feature's gate against a pinned pre-change baseline.

Nothing is breaking. With default settings the only text the model sees differently is the partition line. The `usage` table gains nullable columns. `report-v1`'s `agent_audit` already accepts extra properties. `MODEL_PRICES` and `AI_GATEWAY_PROVIDERS` gain optional fields that old configurations simply omit.

## Non-goals

- No change of models, model aliases, verifier quorum or council policy, triage, the JSON tool protocol (Rio does not move to native tool calling), output limits or turn limits.
- No universal mega-prompt: specialist instructions and schemas are not merged across agents just to create a common prefix.
- No serialization, pre-warming or staggering of verifier voters or council members by default. The live procedure may later evaluate it.
- No Cloudflare AI Gateway response caching. It stays bypassed and separate from provider KV caching.
- No 1-hour or 24-hour retention by default, no OpenAI explicit-breakpoint mode (so no cross-agent reuse claim on OpenAI GPT-5.6+), no Gemini `cachedContents` objects.
- No change to what a QA harness owns (Codex or pi base instructions, tool schemas, compaction, added context items), and nothing for QA subscription mode, which never passes through Rio.
- No feature or hint class turned on by default in this change; only the partition and the accounting are always on.
- No savings estimate in reports, and no cache-hit percentage where the provider did not report cache fields.
- No promotion of owner guidance to a project-wide cached layer. It stays focus-scoped inside the review context (see design D3).
- No paid model calls, deployments or live measurements during this change.

## Acceptance criteria

- Deterministic contract tests (no network) show: identical inputs give byte-identical bodies; each tool follow-up's logical content (system text and the ordered role and text of messages, ignoring cache markers, part splitting and `max_tokens`) begins with the previous request's, and a retry is byte-identical; with `verifier-system` the disclosed turn's logical content begins with the whole blind conversation, and with or without it the hypothesis appears in no request before the blind vote is saved; with `agent-order` a task change alters only the assignment layer and later; with `compaction` the prefix changes only at the first newly elided message and only when the high-water mark is crossed; two tenants diverge at the partition and share the layers before it.
- Every deliberate text change has its own snapshot whose diff from the previous fixture is exactly that change. Wire tests compare renderers on identical logical text, so prompt changes and wire changes are tested separately.
- Per-route request-body tests cover each capability and `PROMPT_CACHE` value: Anthropic built-in, gateway Anthropic, custom Anthropic with and without the capability, OpenAI built-in, `OPENAI_BASE_URL`, OpenRouter Anthropic and non-Anthropic, `compat/`, `dynamic/`, custom OpenAI. Routes without a capability send the plain-string body for their text.
- Usage tests cover the Anthropic, OpenAI and OpenRouter usage shapes with zero, read-only, write-only, mixed and invalid cache use, verified and unverified conventions with every `PROMPT_CACHE` value, and invalid self-hosted counts.
- QA tests (after PR #17 merges) cover transport usage normalization with the harness-visible cached count, cell budgets on total tokens, shape-stable screenshot replacement, transport hints per route with harness cache fields dropped and markers that keep reuse across screenshots more than 20 blocks apart, `qa-order` journey prompts sharing text through the boundary line, and QA voter requests with screenshots inside the cached prefix.
- Partition tests cover per-provider values, concurrent first reviews of a tenant, the secret never leaving Rio, replay after a switch change, and a model echoing the value. Absent fields are null per field. Total input and budget charges match the provider-documented totals; usage reaches the ledger from `converse` and council calls; invalid cache usage on verified routes fails after one transport call with the reservation kept, and on unverified routes is recorded as `invalid` without failing; cost source and value follow the rules for `provider`, `estimate` and `unknown`.
- With every switch at its default, the existing Worker, Rust, runner and eval test suites pass unchanged except for assertions on exact prompt text, which change only by the partition line. Feature-on runs update only layout-dependent assertions, with the reason recorded.
- `openspec validate optimize-llm-prompt-caching --strict` and `openspec validate --specs` pass.

## Capabilities

### New Capabilities
- `prompt-layout`: the ordered prompt layers, deterministic serialization, append-only conversations, the blind-to-disclosed transition, the compaction checkpoint, council request layout, and voter and member independence despite shared prefixes.
- `model-usage`: normalized token usage including cache reads and writes, budget charging, cost sources and estimates, usage persistence, and the prompt-cache audit and report metrics.

### Modified Capabilities
- `model-providers`: adds per-route prompt-cache capabilities and request fields, the deployment-declared capability for custom providers, and response-cache bypass. "Unknown cost stays unknown" now covers cache tokens and optional cache prices.
- `verifier-quorum`: "Two-turn blind verification" now requires the disclosed turn to extend the blind conversation without changing the system prompt, with disclosure instructions and the answer schema arriving only in the second turn.

## Impact

- **Code**: `worker/src/prompt.ts` (new), `gateway.ts` (wire rendering, usage normalization, cost, compaction), `verifier.ts`, `workflow.ts` (agent prompt assembly, council call settle, usage aggregation), `council-pack.ts` (`memberRequest` order), `cache.ts` (layout version in the prompt hash), `storage.ts` (ledger columns, partition table), `types.ts`, `index.ts` (audit columns), `reviews.ts` (switch validation at submission); `crates/rio-cli/src/providers.rs` and `deployment.rs` (optional price and provider fields, prompt settings); `crates/rio-runner/src/model.rs` (cached-token pass-through).
- **Data**: one D1 migration, numbered after the last one on main at implementation time, adding nullable columns to `usage` and the `prompt_partitions` table; after PR #17 merges, a separate migration adds the same columns to `qa_model_usage`.
- **QA code** (after PR #17 merges): `crates/rio-qa/controller/src/{provider-transport,model-proxy,session,cell}.mjs`, the host relay, `worker/src/qa-model.ts`, `qa-verifier.ts` and the QA job specification.
- **Contracts**: optional `agent_audit.prompt_cache` object in the report, optional `cache_read` and `cache_write` in `MODEL_PRICES`, optional `prompt_cache` in `AI_GATEWAY_PROVIDERS`.
- **Coordination**: `rio-v0-3-council` 7.3 runs on a pinned pre-change build, and the council layout task waits for it. Every layout feature and the `anthropic` and `openrouter` hint classes ship off by default; each becomes a default only through a follow-up after its gate passes (design D15).
- **Configuration**: Worker variables `PROMPT_CACHE` and `PROMPT_LAYOUT`, set and validated by `rio deploy` and read once per review. No new secret.
- **Release**: because the partition is always on and model-visible, the commit adding it merges to main only with a passed partition gate (all features off against the pinned baseline) recorded in `docs/evaluation/prompt-caching-gates.json`. A test requires either that record or an explicit pending entry for it, and the pending entry blocks the merge. Groups 0–1 can merge before it.
- **Docs**: a measurement procedure in `docs/evaluation/prompt-caching.md`, the gate record file, and notes in the provider and deployment docs.
